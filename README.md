# Sentinel AML

Real-time anti-money-laundering monitoring platform built with Java 17, Spring Boot, Spring Data JPA, Spring Security, and Flyway.

## What it does
- Ingests customers, accounts, and transactions
- Applies configurable AML rules for CTR threshold, structuring, rapid movement, high-risk jurisdictions, behavioral deviation, and round-number patterns
- Generates explainable, risk-scored alerts
- Opens case files and logs alert/case transitions for auditability
- Serves a simple analyst dashboard with masked PII

## Run locally
```bash
mvn spring-boot:run
```

Default demo credentials:
- `admin / admin123`
- `analyst / analyst123`

## PostgreSQL profile
Set the profile and datasource variables to run against PostgreSQL:
```bash
SPRING_PROFILES_ACTIVE=postgres \
SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/sentinel \
SPRING_DATASOURCE_USERNAME=sentinel \
SPRING_DATASOURCE_PASSWORD=sentinel \
mvn spring-boot:run
```

## Key endpoints
- `POST /api/v1/transactions` - ingest a streaming transaction
- `POST /api/v1/ingestion/customers` - bulk customer ingest
- `POST /api/v1/ingestion/accounts` - bulk account ingest
- `POST /api/v1/ingestion/transactions` - bulk transaction ingest
- `GET /api/v1/alerts` - alert queue
- `GET /api/v1/cases` - case list
- `GET /dashboard` - analyst dashboard
- `GET /swagger-ui.html` - OpenAPI UI

## Rule configuration
Rule thresholds live in the `rule_configs` table and can be updated through `POST /api/v1/admin/rules` or `PUT /api/v1/admin/rules/{configKey}`.

## Seed data
The app loads synthetic customer, account, exchange-rate, rule, and transaction data from `src/main/resources/data/` at startup.

## Demo walkthrough

### 1. Start the app
```bash
mvn spring-boot:run
```

Open:
- `http://localhost:8080/swagger-ui.html`
- `http://localhost:8080/dashboard`

Use the demo credentials:
- `admin / admin123`
- `analyst / analyst123`

### 2. Show the seeded data
The app starts with synthetic customers, accounts, rules, exchange rates, and suspicious transactions already loaded.

Check the alert queue:
```bash
curl -u analyst:analyst123 http://localhost:8080/api/v1/alerts
```

### 3. Demonstrate rule-based detection
The seed data already triggers multiple typologies:
- CTR threshold
- Structuring
- Rapid movement
- High-risk jurisdiction
- Behavioral deviation

Open the alert list in Swagger or dashboard and point out:
- masked customer name
- risk score
- triggered rule
- evidence transaction IDs
- human-readable explanation

### 4. Show dashboard triage
Open `http://localhost:8080/dashboard` and review:
- the sorted alert queue
- masked PII in list view
- existing case records

### 5. Create or ingest a new transaction
Submit a single transaction through the API:
```bash
curl -u analyst:analyst123 -H "Content-Type: application/json" \
  -X POST http://localhost:8080/api/v1/transactions \
  -d '{
    "transactionId": "TXN_DEMO_001",
    "accountId": "ACC_000001",
    "amount": 15000,
    "currency": "INR",
    "counterparty": "Demo Counterparty",
    "channel": "UPI",
    "jurisdiction": "IN",
    "transactionTimestamp": "2026-09-19T12:00:00Z",
    "direction": "CREDIT",
    "transactionType": "DEPOSIT"
  }'
```

Refresh `/api/v1/alerts` to show the new alert generated by detection.

### 6. Open a case from an alert
Create a case for an alert:
```bash
curl -u analyst:analyst123 -X POST http://localhost:8080/api/v1/cases/alerts/{alertId}
```

Then inspect cases:
```bash
curl -u analyst:analyst123 http://localhost:8080/api/v1/cases
```

### 7. Disposition a case
Mark the case as cleared or escalated:
```bash
curl -u analyst:analyst123 -H "Content-Type: application/json" \
  -X PUT http://localhost:8080/api/v1/cases/{caseNumber}/disposition \
  -d '{
    "status": "CLOSED",
    "analystId": "analyst1",
    "reason": "Reviewed and cleared after customer verification"
  }'
```

### 8. Show admin rule tuning
Update a rule without redeploying:
```bash
curl -u admin:admin123 -H "Content-Type: application/json" \
  -X PUT http://localhost:8080/api/v1/admin/rules/CTR_THRESHOLD_BASE \
  -d '{
    "configKey": "CTR_THRESHOLD_BASE",
    "enabled": true,
    "numericValue": 12000,
    "textValue": null,
    "description": "Raised reporting threshold for demo"
  }'
```

### 9. Point out auditability
Every alert and case transition writes an immutable audit event. For the demo, mention that this preserves analyst identity, action, and timestamp for review.

### 10. Close the demo
End by showing:
- alert sorting by risk score
- PII masking in list views
- case disposition history
- configurable AML rules
